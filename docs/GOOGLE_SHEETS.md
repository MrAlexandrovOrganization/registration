# Синхронизация с Google Таблицей

Backend односторонне обновляет **отдельную выделенную вкладку** Google Таблицы
из PostgreSQL. Используется тот же `Service.ExportTable`, что и для `/export`:
те же строки (включая незавершённые анкеты), порядок, заголовки, строковые флаги,
источники и UTC-время. При выключенном участии нет `will_drive`/`trip_attendance`.
Дополнительные вопросы выводятся с читаемыми ответами, как в XLSX.

Телефоны, ID, даты и пользовательский ввод записываются буквальными строками;
формулы не исполняются. Первая строка закреплена и выделена, включён фильтр,
ширина колонок соответствует экспорту, текст переносится. Существующие значения
**всей выделенной вкладки** заменяются, включая удалённые строки и колонки;
другие вкладки не меняются. Собственные расчёты держите на другой вкладке.
Правки из Google в БД не импортируются. На доступ к БД права Google не влияют;
доступ к таблице выдаётся отдельно от Telegram `table_viewer`.

## Подключение

1. Создайте Google Cloud project, включите Google Sheets API. Billing для Sheets
   API не нужен. Создайте отдельный service account **без IAM-ролей проекта**.
2. Создайте JSON-ключ аккаунта и сохраните вне Git. Не передавайте ключ в чате,
   аргументах команд или переменных окружения: приложение читает файл.
3. Создайте таблицу и выделенную пустую вкладку. Дайте email сервисного аккаунта
   доступ «Редактор» **только к этой таблице**. Публичный доступ не нужен.
4. Укажите параметры в приватной `.env`:

   ```dotenv
   GOOGLE_SHEETS_SPREADSHEET_ID=<часть URL между /d/ и /edit>
   GOOGLE_SHEETS_SHEET_ID=0
   GOOGLE_SHEETS_CREDENTIALS_FILE=/absolute/private/path/google-sheets.json
   GOOGLE_SHEETS_SYNC_INTERVAL=1m
   ```

   `SHEET_ID` — числовой `gid` вкладки, не её название. Для `make run` путь читается
   непосредственно процессом; при запуске Compose overlay монтирует этот файл
   read-only в `/run/secrets/google-sheets.json`. Файл должен быть доступен runtime
   UID/GID 10001; на Linux настройте владельца/группу и ограниченные права чтения,
   не делайте ключ общедоступным. `secrets/` исключён из Git и Docker context.
5. Для контейнерного запуска добавьте `compose/docker-compose.sheets.yml` последним
   к текущему `COMPOSE_FILE`, например:

   ```sh
   make config-check
   COMPOSE_FILE=compose/docker-compose.yml:compose/docker-compose.sheets.yml make up
   ```

   Это живая операция. Доставка исходников/образов остаётся штатной Git/CI/CD;
   приватная `.env` и ключ подготавливаются отдельно на выбранной VM. При доставке
   по digest сохраните overlay в её Compose selector и применяйте штатный
   `make image-deploy`, не пересобирайте на VM. Дополнительные overlays текущего окружения сохраняйте перед sheets overlay.

Без ID и файла ключа синхронизация отключена; частичная конфигурация, невалидный
`gid` или интервал вне 10s–24h останавливают старт с безопасной ошибкой.
Ключ не требует открытого браузера и может быть отозван в Google Cloud.

## Доставка изменений и диагностика

Первый снимок отправляется при старте, затем полный снимок каждые 60 секунд
(настраивается). Это периодическая сверка текущего состояния, без очереди и
миграций: изменения, включая прямые SQL и удаления, попадут в следующий успешный
снимок. Промежуточные состояния между сверками не сохраняются. Даже неизменённая
таблица перезаписывается, что также восстанавливает ручные правки и исключает
проблемы локального кеша между репликами. Для небольшого реестра это один read
метаданных и один batch write за интервал. Максимум 50 000 строк, 16 MiB JSON;
большие реестры требуют отдельной стратегии выгрузки.

Каждый снимок читается в Repeatable Read. Одна транзакционная advisory lock в
общей PostgreSQL сериализует writers этого backend; все реплики должны указывать
на одну таблицу и вкладку. Независимые БД нельзя направлять на одну вкладку.
Запись значения/очистка/форматирование выполняются одним атомарным Sheets batch.
При таймауте результат может быть неизвестен, следующий полный снимок безопасно
повторяет запись; при потере соединения с БД абсолютное fencing внешнего API
невозможно. Попытка ограничена 45s, HTTP — 30s, OAuth — 10s. Google недоступен —
бот продолжает работать, повтор после интервала; readiness не зависит от Sheets.
Изменения во время выгрузки попадут в следующую сверку. Ключ и ответы Google
не попадают в логи, чтобы не раскрывать токены и персональные данные.

Логи: `sheets.synced`, `sheets.sync_failed` (без payload). Метрики:
`registration_sheets_sync_total{result="success|failed|skipped"}` и
`registration_sheets_last_success_timestamp_seconds` (0 до первого успеха).
При длительном отсутствии успеха проверьте доступ к таблице, включение API,
валидность ключа, `gid`, квоты и сеть. Отключение: убрать overlay/переменные и
штатно доставить конфигурацию; прежняя таблица сохраняется.

Документация Google: [batch update](https://developers.google.com/workspace/sheets/api/guides/batch),
[service accounts](https://developers.google.com/identity/protocols/oauth2/service-account).
Обычные проверки используют fake HTTP и disposable PostgreSQL; они не пишут в
настоящие Google Таблицы. Live-подключение подтверждается отдельно.
